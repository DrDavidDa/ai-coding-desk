# 无线桌面语音 Coding：产品方案

约束（不可妥协）：**日常使用不插 USB**。收音、按键、把字打进 Cursor / Claude Code / Codex 对话框，全部无线。USB 只用于充电和产测/刷机。

本文是面向市场的形态，不是当前 Python 原型的说明书。

---

## 1. 先把物理限制说死

本硬件是 Waveshare ESP32-S3：**Wi-Fi + BLE 5，没有蓝牙经典（BR/EDR）**。

因此下面三条路 **不能** 作为量产主路径：

| 听起来很美 | 为什么不行 |
|---|---|
| 设备当 Windows 无线麦克风，系统直接听 | 无线麦走的是 HFP/HSP 或 LE Audio。S3 没有经典蓝牙；LE Audio 在 S3 控制器 + 各版本 Windows 上不能当卖点 |
| 板端 ASR，再当蓝牙键盘把中文打进对话框 | S3 做不了产品级中文听写；BLE HID 只发扫描码（Space/Enter），**打不进中文**，Electron 输入框尤其不行 |
| 完全不装 PC 软件 | 无线条件下，Windows 没有「接收自定义麦音频并写入任意输入框」的系统能力。没有宿主进程，中文进不了 Cursor |

结论：**无线 + 板载麦 + 中文进 coding 对话框 = 必须有一个官方 PC 助手。**  
客户麻烦的下限不是「零软件」，而是「装一次、开机自启、以后当它不存在」。这和 Stream Deck / 罗技 Options 是同一档，不是缺陷。

USB 即插即用当系统麦，这条已经排除，不再讨论。

## 2. 产品承诺（对外怎么说）

**打开电脑、点一下 Cursor 对话框、在设备屏上点「录音」说话，再说点「结束」，字出现在光标处。不插线。**

实体键仍在：BOOT 发送、PLUS 可当盲操按住说话（进阶，不是入门必会）。

客户需要做的只有：

1. 从商店安装官方助手（一次，约 30 秒）
2. 开机后用 Windows 自带蓝牙配对设备（一次，和配对键盘一样）
3. 助手勾选「开机启动」（默认勾上）

不需要：USB 数据线操作、填 SiliconFlow Key、配 Wi-Fi 才能说话、在设备上开热点。

Wi-Fi 是 **增值通道**（额度屏、OTA），不是语音能不能用的前提。

## 3. 系统架构

三块无线角色，职责分开：

```
                    蓝牙 LE（日常主通道，不插线）
  ┌─────────────┐   HID：Enter / Esc / n / Shift+Tab
  │  Desk 设备   │   GATT：PTT 音频流（Opus）+ 小状态
  │  ES7210 双麦 │───────────────────────────────────►┌──────────────┐
  │  三键+触屏   │                                    │ 官方助手      │
  │  屏+RGB      │   Wi-Fi（可选，空闲时）              │ 开机托盘      │
  └─────────────┘   额度 JSON / OTA / 音频兜底 ───────►│ SenseVoice    │
                                                      │ Unicode 注入  │
  用户已点中的 Cursor / 终端输入框 ◄── SendInput ──────┘
```

| 通道 | 干什么 | 客户是否要配 |
|---|---|---|
| **BLE HID** | 当一块键盘：BOOT=Enter，长按=Esc，触屏 Yes/No/Mode | Windows 蓝牙配对一次 |
| **BLE GATT 音频** | 触屏点录音（或 PLUS 按住）时把板载麦流到助手 | 同一对蓝牙，助手自动连 |
| **Wi-Fi** | 拉四家额度、固件升级；BLE 拥塞时的音频备用 | **可后配，说话不依赖它** |

助手是唯一能把 **中文 Unicode** 打进 Cursor 的进程。设备不假装自己会打中文。

## 4. 核心路径：说话 → 字出现

这是产品必须 100% 打磨的一条路径。模式名：**板载麦 / 无线**（出厂默认）。

### 4.0 触屏点按，不要按住屏幕

**对外主操作是触屏开关，不是按住实体键。**

原因：

- 对着 1.54 寸屏 **按住** 说话：手指挡住状态、胳膊酸、松手时机难。触屏只适合 **点一下开始 / 点一下结束**。
- 按住 PLUS 适合眼睛不离开显示器的熟手；入门用户会找「录音按钮」，这正是设备内 App 该提供的。
- 编码指令经常超过几秒，按住实体键比点两下更累。

不要做成「必须先滑到 Voice 页才能录」。任何额度页右上角一颗 **麦克风**，点下去就进入全屏录音 App。

### 4.1 用户动作（主）

1. 光标点在 Cursor Chat / Composer（或 Codex 终端）里  
2. 在设备任意页点右上角麦克风，或打开 Voice 页点大按钮 **录音**  
3. 屏幕切到全屏 REC：大红 **结束**、秒数、RGB 提示在录  
4. 说完点 **结束**（或停顿约 1.2 s 自动停，或到上限 12 s）  
5. 约 0.5–1.5 秒后字出现在光标处  
6. 短按 **BOOT** 或触屏 Yes = Enter 发送  

### 4.2 同一套录音状态机（触屏 + 键）

| 怎么开始 | 怎么结束 |
|---|---|
| 点麦克风 / 点「录音」 | 再点「结束」；或尾部静音自动停；或满 12 s |
| 按住 PLUS（盲操） | **松开** PLUS（按住说话，不切全屏也行，避免看键） |

触屏开始的会话：松开 PLUS 不得误停。PLUS 按住开始的会话：点「结束」可以停。HID 热键模式下麦克风按钮改为「按住 Space」的提示，不走板载麦。

板载麦模式下 PLUS **不得** 发 HID Space。

### 4.3 全屏录音 App（设备内）

Idle 各页：配额环照常，角落 mic 约 40 px 热区。

进入录音后 **整屏就是录音 App**（额度先藏起来，避免 240×240 误触切页）：

- 大字 REC + 秒表  
- 巨大「结束」  
- 小「取消」（丢弃、不送 ASR）  
- 禁止滑页、禁止 PWR 切页（PWR 短按在录音中 = 结束，避免慌乱乱点）  

录完回到进入前的那一页，显示 ASR / 上一句。

### 4.4 设备侧（无线收音）

1. 进入录音：关喇叭 PA，ES7210 立体声 16 kHz，**只留左声道（MIC1）**  
2. 丢掉开头几块 DMA 垃圾；边录边 Opus（16 kHz mono，16–24 kbps）  
3. BLE GATT 发给助手  
4. 结束：`END`；太短或静音：`CANCEL`  
5. 录音期间停额度 HTTP；全屏 REC 可以简单，不要在采样时做复杂动画  

不在设备上跑 ASR，不对 SiliconFlow 做 TLS。

### 4.5 助手侧（转写 + 注入）

1. 收齐或边收边送 ASR（松开后再送完整 utterance，第一版更稳）  
2. SenseVoice（你们的服务账号，**客户不填 Key**）；剥 `<|zh|>` 等标签  
3. `SendInput KEYEVENTF_UNICODE` 打进 **当前前台窗口**；失败才剪贴板 Ctrl+V 并恢复剪贴板  
4. **默认不抢焦点、不自动 Enter**  
5. 屏上可回显上一句（经 BLE 小包或稍后 Wi-Fi 状态）  

### 4.6 延迟预算（点「结束」之后）

| 段 | 目标 |
|---|---|
| 末包 BLE + Opus | < 80 ms |
| 云端 ASR | 400–900 ms（国内节点） |
| Unicode 注入 | < 150 ms（约 20–40 字） |
| **合计** | **通常 < 1.2 s** |

第一版允许结束后一次性发 Opus blob。体验不够再改边说边传。

### 4.7 失败怎么表现

| 情况 | 设备 | 助手 |
|---|---|---|
| 没配对 / 助手没开 | RGB 红闪，屏 `NO PC` | — |
| 太短 / 静音 | 不发送，回 IDLE | — |
| ASR 失败 | 屏 `ERR`，保留上一句 | 托盘气泡一次 |
| 焦点不在输入框 | 字打到错误窗口 | 托盘提示「请先点进对话框」 |

## 5. 第二条路径：HID 热键（给 Claude Code 原声）

Claude Code 听的是 **电脑自己的麦**，热键是按住 Space。这是降级/专用模式，不是主卖点。

- 触屏切到 **HID热键 + Claude**  
- PLUS = BLE 按住 Space（系统键盘，助手可以不参与收音）  
- BOOT 仍是 Enter / Esc  

客户若没装助手，**只有这一条能用**（外加 Enter/Esc）。主卖点「板载麦中文进 Cursor」在助手没开时明确提示，不要假装能用。

---

## 6. 触屏 App 与三键怎么分工

**录音主入口在屏上；实体键负责盲操和「发送/打断」。** 不要让客户为了说话去记哪颗侧键。

| 控件 | 板载麦模式 | HID 热键模式 |
|---|---|---|
| 触屏麦克风 / 录音 | 开始·结束录音（主） | 提示改用 PLUS=Space |
| 触屏结束 / 取消 | 送出或丢弃 | — |
| PLUS 按住 | 盲操 PTT（辅，可不开教学） | 按住 Space |
| BOOT 短 | HID Enter | 同左 |
| BOOT 长 | HID Esc | 同左 |
| PWR 短 | 切页；录音中 = 结束 | 切页 |
| PWR 长 3 s | 关机 | 同左 |
| 触屏 Yes / No / Mode | Enter / `n` / Shift+Tab | 同左 |

Voice 页仍保留目标：Cursor / Claude / Codex。只影响助手对窗口标题的提示，默认不自动 Enter。

## 7. 客户生命周期（麻烦最小化）

### 7.1 开箱（目标 ≤ 2 分钟）

1. USB **只充电**，等到能开机；拔掉线，放到显示器旁  
2. 手机或电脑打开商店，安装 **Desk Companion**（签名应用，不是 Python）  
3. 助手全屏引导：「打开 Windows 蓝牙 → 配对 Desk154」  
4. 配对成功后助手显示已连接；引导用户点开 Cursor 对话框，在设备上点「录音」说「测试一下」，再点「结束」  
5. 字出现 → 完成。不出现则检测：前台窗口标题、BLE RSSI、ASR 返回  

没有：配路由器、抄 IP、`host_url`、`sf_api_key`。

### 7.2 每天

开机 → 助手托盘静默 → 设备开机自动回连已绑定电脑 → 说话。  
换电脑：在新电脑装助手并重新配对（一块设备同时只绑一台，桌面产品如此）。

### 7.3 可选（第二天以后）

同一 Wi-Fi 后才有：四家额度环、OTA。助手用 BLE 把 SSID 列表和密码写进设备（蓝牙配网，仍不插 USB）。额度 Token：Claude/Codex 读本机已有登录文件；GLM 在助手里贴一次；Cursor 用浏览器扩展（这是额度问题，不是语音问题，语音不依赖它）。

## 8. 官方助手：必须有，但必须「像没装」

### 8.1 为什么逃不掉

无线设备能当键盘（HID），不能当「会打中文的输入法」。把转写结果送进任意软件的唯一稳定 API 是 Windows `SendInput`，必须由本机进程调用。

### 8.2 产品形态

| 项 | 量产 | 现在的原型 |
|---|---|---|
| 形态 | 微软商店 / 已签名安装包，托盘 | `desk_host.py` |
| ASR 钥匙 | 你们的云账号，按设备证书/序列号鉴权 | 客户自己的 `sf_api_key.txt` |
| 音频入口 | BLE Opus（主），Wi-Fi POST（备） | 仅 Wi-Fi WAV |
| 注入 | 已有 `inject.py` 路线，迁到正式应用 | 同左 |
| 开机 | 默认自启 | 手动跑 |

本机 Whisper 只能作为助手里的「隐私档」，不能替代助手：模型要下载，第一次比云端更麻烦。

### 8.3 权限与安全

- 音频只进已配对助手；GATT 需绑定  
- 不把录音落盘（可开关「保存最后一句用于反馈」）  
- 注入前记录前台窗口标题，便于客服  
- 不做全局驱动、不做虚拟声卡（那比装助手麻烦一个数量级）  

---

## 9. 为何不走「设备自己转文字再无线打字」

1. **听写质量**：S3 没有 NPU；量产中文 coding 指令需要云端或 PC 侧模型。  
2. **注入**：HID 中文不成立；想「设备打字」只能发拼音再赌输入法，coding 场景会翻车。  
3. **换 SoC 也救不了注入**：就算板端 ASR 完美，没有 PC 进程仍进不了 Cursor。除非改硬件加经典蓝牙当系统麦，那是另一块 BOM，且 HFP 音质差，仍不如「板载麦 + 助手 ASR」。  

若未来做「无助手 SKU」，只能卖成 **无线快捷键盘**（Enter/Esc/Space），不能承诺板载麦中文听写。不要用同一句广告词覆盖两个 SKU。

---

## 10. 射频、功耗、共存

- 说话时 **优先只开 BLE**；Wi-Fi 与 BLE 同天线共存时录音丢包，故录音窗口暂停额度 HTTP  
- 桌面距离 1–3 m，BLE 5 足够；金属显示器后方可能要贴前缘  
- Opus 24 kbps × 12 s 远小于 BLE 5 实际吞吐；不要第一版就上未压缩 PCM over BLE  
- 电池：PTT 时 ES7210 + BLE TX 是峰值；屏 240×240 已比墨水屏费电，空闲降亮

## 11. 和当前仓库的关系（原型 → 产品）

已有、可保留：

- 板载麦左声道、PA 关闭、静音门限、异步上传  
- `inject.py` Unicode 注入  
- BLE HID Enter/Esc/Space  
- 额度聚合与 LVGL 分页  

必须改才能符合本方案：

- 音频主通道从 **Wi-Fi WAV** 改为 **BLE Opus**（Wi-Fi 留作备用）  
- 助手从 Python 脚本变为可分发应用；ASR Key 从客户侧移到你们云  
- 配网从串口/`host_url` 改为蓝牙配网  
- PLUS 在板载麦模式禁止 HID Space  

未烧录、未做真机 BLE 音频吞吐测试前，量产风险第一项就是：**Windows 同时占 HID 与自定义 GATT 是否稳定**。过不了则退路为「按键也走 GATT，由助手模拟 Enter」（助手必须在跑，与「助手本就要在」一致）。

## 12. 分期

| 期 | 交付 | 客户麻烦 |
|---|---|---|
| 现在（打样） | Wi-Fi WAV + Python 助手 + BLE 键 | 高，仅内部 |
| **P0 可卖语音** | BLE 音频 + 签名助手 + 商店/安装包 + 你们的 ASR 账号 | 装一次 + 配对一次 |
| P1 | 蓝牙配网、额度、OTA、无 Wi-Fi 也能说话（P0 已基本满足） | 不变 |
| P2 | 本机 Whisper 档、Mac 助手 | 可选 |

P0 的验收口令：**拔掉 USB，只开蓝牙和助手，点屏录音说中文再点结束，字出现在 Cursor 对话框。**

## 13. 决策摘要

- 日常 **不插 USB**。  
- **录音主操作 = 触屏点按开始/结束**（设备内录音 App）；PLUS 按住是盲操快捷，不是入门路径。  
- 无线麦必须 **板载录 + BLE 传给助手**。  
- 中文进对话框必须 **助手 SendInput**。  
- 客户最小麻烦 = **一个会自启的官方助手 + 一次蓝牙配对**。  
- Wi-Fi 不是说话的前提。
